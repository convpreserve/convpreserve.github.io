Testing Conversation Preservation Across LLM APIs

LLM API translators can silently change instructions, tool interactions, error states, and generation controls, even when translated requests remain valid. ConvPreserve provides a deterministic, rule-based oracle to identify these changes and assess whether conversation information survives translation.

Getting Started

    

      

        

          1. Install & verify bundled reference suite
          
        

        
$ git clone https://github.com/convpreserve/conv-preserve
$ cd conv-preserve && pip install .
$ convpreserve selftest

          2. Check a pair or a JSONL manifest
          
        

        
$ convpreserve check --side request \

Documentation

    

      

        
          
SubcommandKey optionsBehavior

        
        
          
convpreserve check--side --src-dialect --dst-dialect [--json | --format github]Compare one source payload and its translated counterpart (- reads stdin).

          
convpreserve batchMANIFEST [--out FILE] [--summary-md FILE] [--fail-on T1|T2|T3|none]Judge every JSONL manifest entry and aggregate counts by rule and dialect pair.

          
convpreserve probe--gateway URL --target {openai,responses,gemini,anthropic}Start a local loopback sink, send 51 Anthropic request shapes, and judge forwarded traffic.

          
convpreserve explainRULE | --list [--json]Show rule definition, tier, principle, and curated translator root causes (S03–S09).

          
convpreserve selftest[--oracle v1.0 | v1.3]Replay the 400-call stratified sample and 174 per-rule positive/negative cases.

          
convpreserve dialects—List canonical dialect identifiers and short aliases (openai, responses, anthropic, gemini).
